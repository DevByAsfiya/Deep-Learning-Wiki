# Tag Taxonomy

A controlled vocabulary. Free form tagging turns into forty spellings of the
same idea, so tags come from this list. Adding a tag means adding it here first.

---

## Domain tags

| Tag | Scope |
| --- | --- |
| `#foundations` | Maths, core neural network theory |
| `#computer-vision` | Anything image or video |
| `#nlp` | Text and language |
| `#speech-audio` | Audio, speech recognition, synthesis |
| `#sequence-models` | RNNs, time series, forecasting |
| `#generative` | GANs, diffusion, autoencoders, flows |
| `#reinforcement-learning` | RL and alignment via RL |
| `#multimodal` | Two or more modalities in one model |
| `#graph` | Graph neural networks |

## Method tags

| Tag | Scope |
| --- | --- |
| `#architecture` | A new model structure |
| `#optimization` | Optimizers, learning rate schedules |
| `#regularization` | Dropout, weight decay, augmentation |
| `#normalization` | Batch norm, layer norm, and relatives |
| `#attention` | Attention and transformer mechanics |
| `#transfer-learning` | Pretraining, fine tuning, adaptation |
| `#self-supervised` | Learning without labels |
| `#efficiency` | Quantization, distillation, pruning, sparsity |

## Practice tags

| Tag | Scope |
| --- | --- |
| `#ml-strategy` | How to prioritise and structure a project |
| `#error-analysis` | Diagnosing what is actually wrong |
| `#deployment` | Serving, latency, infrastructure |
| `#monitoring` | Drift, observability, retraining |
| `#evaluation` | Metrics and benchmark design |
| `#data` | Collection, labelling, cleaning, augmentation |

## Quality tags

| Tag | Scope |
| --- | --- |
| `#foundational` | Changed the field, read it eventually |
| `#practical` | Directly useful when building |
| `#reference` | Worth returning to, not worth reading start to finish |
| `#historical` | Important context, superseded in practice |

## Status tags

| Tag | Means |
| --- | --- |
| `#complete` | Written and reviewed |
| `#draft` | Written, not reviewed |
| `#stub` | Placeholder |
| `#needs-code` | Explanation is done, implementation missing |

## Rules

1. Every note carries **one domain tag** and **at least one method or practice
   tag**.
2. Paper notes additionally carry **one quality tag**.
3. Do not invent tags in a note. Add them here first, with a scope line.
4. If two tags always co-occur, merge them.
